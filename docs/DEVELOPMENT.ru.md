# Разработка аддонов 4FusionLab

[English](DEVELOPMENT.md)

## Архитектура

- `CommunityStore/CommunityStore.py` и `bootstrap.py` содержат постоянную точку входа Fusion и выбор версии. Оба модуля загружаются без `adsk`.
- `CommunityStore/runtime.py` отвечает за команды Fusion, палитру и жизненный цикл событий. Модуль импортирует `adsk`.
- `CommunityStore/config.py`: стабильный идентификатор команды и метаданные продукта. Создаётся один раз.
- `CommunityStore/core.py`: обычный Python, независимо тестируемые вычисления и предметная логика.
- `CommunityStore/CommunityStore.manifest`: метаданные аддона Autodesk Fusion; сборщик релиза записывает вычисленную версию в ZIP, не меняя рабочий каталог.
- `scripts/build.py`: детерминированный архив, SHA-256, защита от секретов и символических ссылок.
- `.github/release-paths.txt`: проверенный перечень файлов, влияющих на поставляемые компоненты.

## Работа над Community Store

Проект уже инициализирован. Сохраняйте UUID манифеста и идентификаторы команд Fusion. Ведите разработку в ветке, выполняйте проверки ниже и привязывайте нативную приёмку к SHA-256 проверенного ZIP. Слияние поставляемых изменений в `main` может опубликовать стабильный релиз после успешного CI. До слияния требуется решение о выпуске.

## Локальная проверка

Палитра и сообщения аддина используют английский и русский JSON-каталоги из `CommunityStore/locales/`. Ключи и имена параметров должны совпадать. Для строк палитры используется префикс `ui.`, а статические подписи помечены атрибутами `data-i18n` в HTML. Описание аддина Fusion читает из манифеста.

По умолчанию язык палитры определяется по языку интерфейса ОС, для остальных языков используется английский. Язык можно сразу изменить в разделе **Настройки → Язык интерфейса**. Выбор сохраняется в профиле Fusion.

```bash
python scripts/check_project.py
python -m unittest discover -s tests -v
python scripts/build.py --version 1.0.0
```

Неинициализированный исходный шаблон можно тестировать с `--allow-template`, но он **не может** публиковаться; новые продукты не должны использовать этот флаг в сценариях релиза.

## Установка в Fusion

В разделе Assets релиза Community Store 1.0.0 на GitHub доступны ZIP аддина Fusion, установочный EXE для Windows и DMG для macOS. Оба сетевых установщика для этого релиза собраны из [коммита `af5eaab`](https://github.com/4FusionLab/CommunityStore/commit/af5eaab2e08a9547cf795d082451183324096908). Чтобы повторить сборку, перейдите на этот коммит и выполните на macOS команду ниже.

```bash
python scripts/build_installers.py --platform all
```

Для обеих платформ загрузчик собирается с помощью Go. Используйте `--platform windows` при наличии NSIS 3 в PATH или `--platform macos` на Mac с Xcode Command Line Tools. Установщики и их файлы SHA-256 появятся в `dist/installers/`.

Установщик скачивает последний стабильный релиз `4FusionLab/CommunityStore` с GitHub. В каждом стабильном релизе должны быть стандартный `CommunityStore-VERSION.zip` и соответствующий файл `.zip.sha256`. Для первой установки нужен интернет. При выходе новых версий Store установщик пересобирать не требуется.

После успешной первой установки и закрытия окна Windows-установщик перемещает запущенный EXE с локального диска в Корзину. На macOS приложение пробует извлечь образ, из которого его открыли, и перемещает этот DMG в Корзину. Если установка прервалась или завершилась ошибкой, файл остаётся для повторной попытки.

Перед загрузкой сверьте каждый готовый установщик с файлом SHA-256, который создал сборщик. Смонтируйте DMG и проверьте приложение установки. На тестовой Windows запустите Setup и проверьте весь процесс скачивания и установки аддина.

В чистом пользовательском профиле закройте Fusion и запустите установщик. Откройте Fusion и проверьте **Design → Utilities → Add-Ins → Community Store**. Команда должна появиться без ручной регистрации и нажатия **Run**. Откройте каталог без входа в GitHub и снова перезапустите Fusion, чтобы проверить, что команда остаётся доступной. Повторите на Windows и macOS с файлами, скачанными через браузер. Если Community Store уже зарегистрирован из другой папки, используйте существующую установку, чтобы избежать дубликатов.

Для ручной установки из ZIP:

1. Скачайте ZIP из GitHub Releases продукта или соберите его локально.
2. Распакуйте его так, чтобы каталог Fusion API AddIns содержал `CommunityStore/CommunityStore.manifest` и `CommunityStore/CommunityStore.py`. Не устанавливайте ZIP с двойной вложенностью каталогов.
3. Откройте Autodesk Fusion, перейдите в **Utilities → Add-Ins** и запустите аддон. Проверьте запись аддона на панели SOLID **ADD-INS**.
4. Откройте **Community Store** и проверьте список аддинов Fusion. Остановите Community Store и убедитесь, что палитра и команда исчезли.
5. Повторите на macOS и Windows для зависимостей, геометрии и интерфейса, специфичных для ОС, отмечая различия. Не утверждайте, что CI выполнил приёмку в Fusion.

## Контрольный список приёмки в Fusion

- В режиме **Как в системе** проверьте русский и английский языки ОС и переход на английский для неподдерживаемого языка. Переключите язык вручную, проверьте подписи, сообщения и подсказку кнопки Fusion. Перезапустите аддин и убедитесь, что выбор сохранился.

- Установка, запуск, остановка и повторный запуск без дублирующихся элементов управления и утечек обработчиков.
- В разделе **Мои аддины** выберите совместимый аддин из папки вне каталогов Store и Fusion API. Убедитесь, что Fusion зарегистрировал его по исходному пути, а в Store доступны запуск, остановка и автозапуск. Проверьте, что при повторном выборе папки Store сообщает о существующей регистрации, а при отключении файлы сохраняются.
- Команда открывается, отменяется и выполняется; результат корректен и безопасен.
- Переключение активного документа, отсутствие документа и удаление модели не приводят к небезопасной записи.
- Где применимо, проверьте параметрическое и прямое моделирование, обновление таймлайна, единицы, отмену и повтор действий.
- Взаимодействия с CAD API, порядок событий интерфейса, жизненный цикл предпросмотра и производительность проверены внутри Fusion.
- ZIP релиза содержит корректный манифест, согласованную с GitVersion версию и контрольную сумму.
- Проверьте переносимость между ОС, нативные зависимости и необходимую подпись.
- Поддерживайте точность документации EN/RU и публикуйте реальные ограничения.

## Журнал диагностики

После воспроизведения сбоя откройте **Настройки → Диагностика → Выгрузить логи…** и сохраните ZIP. Передайте его в поддержку вместе с шагами воспроизведения и примерным временем сбоя. Журнал хранится локально, пользователь сам передаёт архив.

В архиве до четырёх файлов по 512 КиБ. Время записей указано в UTC. В журнал входят версии Store и Fusion, этапы операций, типы ошибок и места сбоя в коде Store. Учётные данные OAuth, коды входа, URL, локальные пути и данные CAD в журнал не включаются.

Если Store не открывается, возьмите `community-store.log` и его нумерованные копии из папки `~/Library/Logs/4FusionLab/CommunityStore/` на macOS или `%LOCALAPPDATA%\4FusionLab\CommunityStore\Logs\` на Windows.

При приёмке на обеих платформах выгрузите журнал после проверки релизов и убедитесь, что в ZIP есть события проверки с отметками времени. Отмените повторную выгрузку и убедитесь, что файл не появился.

## Опциональный вход в GitHub

Список источников Marketplace сохраняется в локальном профиле Fusion и доступен с подключением к GitHub и в анонимном режиме. В разделе **Настройки → GitHub** нажмите **Войти в GitHub**, откройте GitHub в браузере и введите код из палитры. Кнопка **Выйти** удаляет локальный токен из macOS Keychain или Windows Credential Manager. Чтобы отозвать разрешение приложения на стороне GitHub, откройте [Authorized OAuth Apps](https://github.com/settings/applications).

Сборка использует публичный Client ID приложения Community Store из `CommunityStore/config.py`. Если вы распространяете собственную сборку, зарегистрируйте своё OAuth-приложение GitHub и включите **Enable Device Flow**. Для локальной проверки можно вместо этого задать `COMMUNITY_STORE_GITHUB_CLIENT_ID` в окружении, из которого запускается Fusion. Если токен выпущен со сроком действия, после его истечения потребуется повторный вход. Device Flow не требует встроенного client secret. Store запрашивает пустой список scopes. [GitHub Device Flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow)

На macOS и Windows проверьте просмотр каталога без входа, подтверждение и отмену входа и восстановление сеанса после перезапуска Fusion. Убедитесь, что после выхода снова доступен анонимный режим с прежними источниками. Отзовите разрешение приложения на GitHub и проверьте, что следующая проверка каталога возвращает аддин в анонимный режим. Проверьте, что пауза по анонимному лимиту не блокирует проверку после входа, а запросы на загрузку ZIP и изображений идут без OAuth-токена.

В настройках показаны имя, логин и аватар аккаунта. После входа Store использует квоту авторизованных запросов GitHub REST API для публичного каталога. [Лимиты REST API](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

## Жалобы на аддины и источники

Откройте окно жалобы на странице аддина и в списке источников каталога. Проверьте, что отмена возвращает в прежний раздел, а переход к публичному черновику открывает на GitHub предзаполненный черновик на выбранном языке. Для аддина подставляются публичный репозиторий каталога и отображаемый тег релиза, если они известны. Для источника подставляется имя выбранного владельца GitHub. В оба черновика подставляется версия Store. Проверьте черновик в браузере и оставьте его без отправки. Кнопка для конфиденциальных сообщений открывает локализованную [политику безопасности](../SECURITY.ru.md) с инструкциями по закрытой отправке.

GitHub загружает четыре формы из `.github/ISSUE_TEMPLATE/` в ветке по умолчанию. Идентификаторы полей в формах должны совпадать с параметрами ссылки в `CommunityStore/reporting.py`.

## Самообновление Community Store

При проверке по расписанию Store также запрашивает последний стабильный релиз публичного репозитория `4FusionLab/CommunityStore`. Если релиз новее запущенной версии, нажмите **Обновить до** в строке Community Store на вкладке **Мои аддины**. Store скачивает `CommunityStore-<версия>.zip` и проверяет SHA-256 из GitHub, идентификатор и версию в манифесте, а также совместимость с ОС.

Один раз установите сборку с загрузчиком. При включённом **Run on Startup** следующий запуск Fusion попробует запустить подготовленную версию. Если запуск завершится ошибкой или прервётся, загрузчик вернёт последнюю успешно запущенную версию. Встроенная версия доступна как резервная. Зарегистрированная точка входа и манифест остаются на своих местах, поэтому менеджер Fusion может показывать исходную версию. Фактическая версия указана в палитре Store. Профиль Fusion и папка `CommunityStore/AddIns` сохраняют свои пути.

Рабочие копии Git и установки по символическим ссылкам запускают локальный код. Изменения самого загрузчика требуют ручной установки. Контракт `runtime.run` и формат состояния обновления должны оставаться совместимыми с ранее выпущенными загрузчиками.

Для проверки в Fusion используйте отдельную тестовую установку с включённым **Run on Startup**. Проверьте первый запуск, подготовку новой сборки, её активацию после перезапуска Fusion и откат со сборки, которая выдаёт ошибку при запуске. На каждом этапе убедитесь, что сохранились настройки, путь регистрации и управляемые аддины. Повторите проверку на macOS и Windows.

## Политика релизов

Общие Actions закреплены за коммитом `2e961620a068c3ad754f6e1be05fb6e4ac68e843` репозитория 4FusionLab/.github. Основным источником является [RELEASE_PLATFORM.md](https://github.com/4FusionLab/.github/blob/main/RELEASE_PLATFORM.md). Изменения кода продукта дают право на релиз, когда пути файлов совпадают с `.github/release-paths.txt`; до публикации должны пройти все обязательные межплатформенные тесты и проверка ZIP.

Community Store распространяется по [PolyForm Noncommercial License 1.0.0](../LICENSE). Полный текст входит в ZIP в файле `CommunityStore/LICENSE`. Для иконок Lucide и библиотеки markdown-it в комплекте сохранены [условия их лицензий](../CommunityStore/ui/vendor/).
